## Context

参见 [proposal.md](./proposal.md) 的 Why。本项目已经存在会话存储、确定性图像分析、检测动作评估、风险预算、质量门控、证据图谱和本地模型客户端的部分 Python 原型，但尚未形成可启动应用、本地知识库、双机拓扑、前端、部署包和测试闭环。

本次设计受以下约束影响：

- 可实施时间为一天，演示必须稳定、可重复，并能在没有真实 Raman/HSI/XRF 仪器时明确使用回放适配器。
- 两台 DGX Spark 位于同一受控局域网，作为一套系统协同运行；数据和知识库默认不离开本地网络。
- 演示的重点是科学工作流与证据治理，模型不得直接给出真伪、断代、价格或法律结论。
- 服务需要在 Spark 的 ARM64 环境运行，优先采用 NVIDIA 官方容器和 OpenAI-compatible 接口，应用层保持模型可替换。
- 当前参考资料尚未完成专家审核，因此内置条目和测量值只能作为 `DEMO/SYNTHETIC` 数据使用。

## Goals / Non-Goals

**Goals:**

- 用一条端到端链路展示“感知—检索—规划—检测—质量门控—证据更新—报告”的产品差异。
- 让两台 Spark 形成清晰的数据流和调用链，同时允许通过配置交换角色或降级到单机。
- 实现真实可查询、可版本化、带来源元数据的本地知识库，并让每次检索进入审计链。
- 使风险预算更新、检测质量失败和弃权行为可测试、可解释、可复现。
- 保证演示中的模型输出、规则输出、回放数据和专家结论边界清楚可见。

**Non-Goals:**

- 一天版本不构建通用文物鉴定基础模型，也不宣称达到法定鉴定或实验室认证能力。
- 不接入真实仪器控制协议；仅定义稳定适配器契约并实现回放适配器。
- 不实现跨两台 Spark 的张量并行或训练集群；双机通过私网服务调用协作。
- 不在本次交付中建立生产级多租户、计费、机构 SSO、灾备集群或大规模数据标注平台。
- 不把模型生成文本当作事实来源；模型只能形成观察建议或基于已准入证据的受限摘要。

## Decisions

### 1. 采用“计算平面 + 知识证据平面”的协同双节点

```text
浏览器
  │ HTTPS / 私网
  ▼
Spark B：RelicScope Gateway
  ├─ 会话 / P01 编排 / 风险账本
  ├─ 本地知识库 / 证据图 / 审计链
  ├─ 报告 / Web UI / 可选推理模型
  │
  └──受控私网 API──► Spark A：Multimodal Compute
                      ├─ VLM 图像观察
                      ├─ 视觉指纹 / 嵌入
                      └─ 相似样本检索计算
```

选择该拓扑的原因是将两个持续占用显存的模型分散运行，并让知识、证据与业务状态集中持久化。浏览器只访问 Spark B；Spark A 的模型端口不对用户网络公开。角色由环境配置决定，应用不依赖固定主机名或硬编码 IP。

备选方案是两机张量并行运行一个超大模型。它能展示更大的模型，但会增加网络、容器和并行运行时的不确定性，也无法体现 RelicScope 的科学工作流，因此不用于一天版本。后续可作为大模型推理模式加入。

### 2. 模型服务与科学决策解耦

Spark A 默认运行 NVIDIA 支持的 Qwen2.5-VL 7B NVFP4 视觉模型；Spark B 可选运行 Qwen3 14B NVFP4 形成报告摘要。应用通过 OpenAI-compatible API 调用模型，并记录模型标识、提示词哈希、延迟、输出摘要和失败状态。

科学决策由确定性应用代码执行：风险预算、动作过滤、信息价值、质量门控、证据准入和停止条件均不委托给语言模型。模型不可用时，系统进入可见的 degraded 状态，继续使用确定性图像指标、词法/向量检索和模板报告，且不得伪装为模型已运行。

备选方案是让 Agent 自主决定检测动作。该方案难以稳定复现安全硬约束，也不利于测试和审计，故不采用。

### 3. 本地知识库采用版本化清单、分块索引与可替换嵌入接口

知识条目保存以下最小元数据：`source_id`、题名、机构/作者、发布日期、来源 URI 或本地文件名、内容 SHA-256、许可说明、适用器物/材质/检测模态、专家审核状态、数据等级和索引版本。文档分块后同时建立全文索引与向量索引；查询结果必须返回分数、引用片段和来源元数据。

一天版本提供可直接运行的本地索引和少量合成/公开示例条目。嵌入计算通过统一接口调用 Spark A；接口不可用时使用确定性特征与全文检索降级。后续可以在不改变会话、检索结果和证据接口的情况下切换 Qdrant、pgvector 或专用嵌入模型。

备选方案是第一天即引入 Neo4j、Qdrant、对象存储和消息队列四套基础设施。它会增加部署面和失败点，超出一天演示的必要复杂度；本设计先固定行为契约，再保留存储替换边界。

### 4. 原始数据、派生结果和知识引用采用不同证据等级

系统对每个上传文件计算 SHA-256 并只追加登记。派生的图像质量指标、视觉指纹、模型观察、检索结果和仪器结果分别成为证据图节点，边表达 `derived_from`、`supports`、`conflicts_with`、`measured_at` 和 `cites` 等关系。

数据等级至少包括：

- `RAW_CAPTURE`：原始采集文件及其哈希；
- `DERIVED_MEASUREMENT`：算法或仪器产生、通过质量门控的结果；
- `MODEL_OBSERVATION`：模型可见事实描述，不能独立支持鉴定结论；
- `REFERENCE_SOURCE`：带来源和适用范围的知识条目；
- `DEMO_SYNTHETIC`：合成样本或回放数值，任何界面与报告必须显示标签。

证据图一天版本使用应用可控的 JSON 图结构并随会话事务持久化，避免额外图数据库；图结构保持可导出，以便后续迁移。

### 5. P01 采用“硬约束优先、原子预留、先结算后门控”的状态机

候选动作先进行硬过滤：区域/模态风险预算、风险通道锁定、同参数失败重试抑制。可行动作按下式排序：

```text
expected_information_gain = pass_rate × max(0, current_uncertainty - expected_uncertainty)
utility = α × expected_information_gain - β × normalized_cost - γ × risk_ratio
```

选中动作时，在同一事务中原子预留预计物理负荷，防止并发超预算。执行后严格按以下顺序处理：

1. 记录设备结果和遥测；
2. 将实际物理暴露结算至风险账本，遥测无效时按保守值结算并锁定通道；
3. 执行校准、信噪比、饱和、区域匹配和参考适用性质量门控；
4. 仅当质量通过时更新命题，否则保持不确定度、抑制原参数重试并重新规划；
5. 没有安全且有价值的候选动作时显式弃权。

演示固定展示一个可复现路径：Raman 被选中后因低信噪比失败，实际光照风险仍被扣除；XRF 因预算不足被拦截；系统改选 HSI，通过质量门控后将关键命题不确定度从 0.85 降至 0.48 并停止继续检测。数值均标记为回放数据。

### 6. 事务存储与哈希链保证可验证状态演进

会话更新和审计事件在同一个数据库事务中完成。每个审计事件包含前一事件哈希，当前哈希由规范化 JSON 计算。报告生成时包含最终事件哈希、原始文件哈希、知识库版本、模型运行记录和证据图摘要，并另行计算报告包哈希。

哈希链只证明记录在生成后是否被改变，不证明输入事实真实或机构签章有效。生产版需要数字签名、可信时间戳、权限审计和独立留存，本次仅在报告中明确该边界。

### 7. 使用单入口 API 与无构建依赖的演示界面

Spark B 提供统一 REST API 和静态 Web 界面。接口包括健康状态、会话创建/读取、图像分析、知识检索、动作规划/执行、证据图、审计校验和报告生成。写操作通过会话状态机拒绝非法顺序并返回明确错误。

界面突出五个可见卖点：双节点在线状态、本地知识引用、风险预算、动作选择理由、证据图与审计哈希。一键演示只串联真实 API，不在前端伪造状态。无外部 CDN，使离线部署可用。

### 8. 仪器适配器保持真实接入路径

统一适配器输入为动作、区域、参数和风险预留；输出为原始结果引用、实际风险遥测、质量指标、发现描述、证据状态及设备/校准元数据。回放适配器返回同一数据结构，且 `demo_data=true`。

后续接入真实设备时，只替换适配器和数据解码器；风险结算、质量门控、证据图、审计和报告不变。这样一天版本验证的是未来生产系统仍会使用的核心控制面。

### 9. 部署和安全边界

- 两机模型接口和知识服务只绑定私有网络地址；对浏览器仅开放 Spark B 网关端口。
- 节点间请求使用 API key；密钥通过环境或 Docker secret 注入，不进入镜像、日志和代码库。
- 容器使用固定版本标签、非 root 应用用户、持久化数据卷和健康检查。
- 上传限制 MIME 类型、文件尺寸和图像解码；服务端重新生成安全文件名。
- 模型端口、分布式运行时端口和数据库端口不得暴露到公网。
- 默认关闭外部遥测与云模型调用；健康页明确显示当前是否处于本地、降级或演示模式。

### 10. 成熟框架优先，并以适配器隔离科学方法

当前可运行模型路径复用 NVIDIA DGX Spark 官方 playbook 所采用的 vLLM 容器和 OpenAI-compatible 接口。应用层不重复实现模型服务、张量运行时或 GPU 调度。小规模演示知识仍使用版本化本地索引，因为它更容易离线复演和逐条审计；NeMo Retriever、cuVS/Milvus 只在授权文献和参考样本规模达到必要性后引入。

真实科学数据按统一结果信封接入。Raman、XRF、HSI 与三维数据分别优先评估 RamanSPy、PyMca、Spectral Python 与 Open3D；实时相机和传感器阶段再评估 Holoscan / Sensor Bridge 与 DeepStream PyServiceMaker。第三方组件只产生带软件版本、输入哈希、校准引用、质量指标、来源与许可证信息的测量结果，不直接修改命题、风险账本或报告结论。

表面异常检测优先评估 anomalib，但异常分数只表示相对训练分布的偏离，不等同于真伪、年代、窑口或修复结论。MVTec AD 的非商业数据不得进入商业交付；许可证或数据来源不清的陶瓷缺陷仓库不得下载或打包。状态必须区分 `DEPLOYMENT_READY`、`HARDWARE_VERIFIED`、`ADAPTER_READY`、`EVALUATION` 与 `PHASE_2`，不得仅因架构图或文档出现组件名称就声称已经集成或已经在目标设备运行。

## Risks / Trade-offs

- [内置知识条目数量少，可能被误解为真实专家库] → 全部标记 `DEMO/SYNTHETIC`，提供清单、来源字段和专家审核状态；演示口径只证明架构与检索流程。
- [本地视觉模型可能首次下载耗时或受模型许可限制] → 提前缓存容器和权重，提供离线预检与确定性降级；部署到欧盟前重新选择/审核视觉模型许可。
- [双节点网络中断使感知服务不可用] → 网关超时后进入 degraded 模式，显示故障并继续确定性分析，保留重试和单机改配方案。
- [回放数据过于顺滑，削弱真实性] → 演示包含一次故意的质量失败、风险仍结算和重规划，并在所有层级显示回放标签。
- [规则阈值来自演示假设，不能直接用于实物] → 阈值与协议版本化，报告列出协议版本；真实部署前由文保专家、设备工程师和机构安全负责人共同校准。
- [SHA-256 审计链被误认为可信认证] → 界面和报告明确其完整性边界，后续引入机构签名与可信时间戳。
- [一天内引入过多基础设施降低成功率] → 首版使用单应用持久层与可替换接口，优先完成可测试的行为；外部向量库与图数据库作为后续替换项。

## Migration Plan

1. 将现有部分原型标记为 brownfield 基线，先运行静态检查和单元测试，记录缺口。
2. 完成本地知识库、应用编排和 REST API，使单机确定性模式端到端通过。
3. 接入 Web 界面和一键演示，验证所有 `DEMO/SYNTHETIC` 标签与保守结论。
4. 在 Spark A 启动视觉模型/嵌入服务，在 Spark B 启动应用和可选推理模型；通过私网地址配置服务发现。
5. 运行预检、集成测试和固定演示脚本，导出一次完整报告包并验证审计链。
6. 回滚时停止新容器，恢复前一镜像标签和持久化卷快照；知识库索引可由版本化清单重新构建。

## Open Questions

- 首批正式知识库的版权许可、专家审核流程和机构签章方式将在生产化阶段确定；这些选择不会改变一天版本的知识条目元数据和引用接口。
- 真实 Raman、HSI 与 XRF 设备品牌和 SDK 尚未确定；适配器契约已隔离该差异，接入任务在设备确定后展开。
