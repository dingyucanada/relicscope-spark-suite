## Why

RelicScope AI 需要在一天内形成可真实运行、可在两台 NVIDIA DGX Spark 上本地部署的演示系统，用一条完整证据链证明产品的核心技术价值，而非只展示界面或模型对话。当前已有部分后端原型，但缺少统一需求、双节点协作、本地知识库、可验证验收标准和完整部署交付。

## What Changes

- 建立面向古陶瓷首发场景的科学鉴证会话，统一记录器物声明、观察区域、原始文件哈希、检测动作、模型运行和证据状态。
- 实现 RGB 图像质量检查、确定性视觉指纹、多模态观察和可解释的相似样本召回。
- 部署可离线使用的本地知识库，区分资料来源、适用范围、版本和引用，并支持图像与文本检索。
- 实现 P01 主动科学检测协议：按预期信息增益、成本与物理风险选择下一检测；执行前原子预留风险预算，执行后先结算实际暴露，再进行质量门控和命题更新。
- 实现 Scientific Evidence Graph、哈希链审计、保守结论与结构化报告；系统不输出真伪、年代、价格或法律结论。
- 将两台 Spark 组成同一套私有网络系统：Spark A 承担多模态感知、向量化和检索计算，Spark B 承担知识与证据服务、检测编排、推理、API 和界面；角色通过配置解耦并支持单机降级。
- 提供一键演示路径、可替换的仪器回放适配器、容器化部署、健康检查、测试和操作说明。
- 所有回放检测值和内置参考样本必须显著标记为 `DEMO/SYNTHETIC`，不得与真实仪器数据或经专家审核的参考库混淆。

## Capabilities

### New Capabilities

- `artifact-session`: 器物建档、命题、观察区域、原始文件与会话状态的统一管理。
- `multimodal-perception`: 图像质量门控、视觉指纹、模型观察及可追踪模型运行。
- `local-knowledge-retrieval`: 本地知识入库、版本化、来源引用、向量检索和离线降级。
- `active-scientific-sensing`: 安全硬约束、信息价值计算、风险预算预留/结算、质量门控、重规划与弃权。
- `evidence-chain-reporting`: 科学证据图谱、哈希审计链、保守结论和可验证报告包。
- `dual-spark-runtime`: 双 Spark 私有网络协作、服务健康、角色配置、故障降级和部署安全。

### Modified Capabilities

无；项目尚无已归档的 OpenSpec 主规格。

## Impact

- 影响 FastAPI 后端、浏览器演示界面、SQLite/本地向量知识库、模型与仪器适配层、测试和部署脚本。
- 新增 OpenAI-compatible 本地推理接口、向量检索服务接口和双节点健康检查；默认不依赖公网服务。
- Spark A 运行视觉语言模型与嵌入服务；Spark B 运行应用、知识库、证据存储与可选推理模型。两节点之间只暴露受控的私网 API。
- 一天版本使用确定性算法与带标签回放数据保证可复现；真实仪器、经许可模型和专家知识库通过相同接口后续接入。
- 交付物包括源代码、OpenSpec 文档、样例知识库、容器配置、部署/回滚说明、测试结果和 5 分钟演示脚本。
