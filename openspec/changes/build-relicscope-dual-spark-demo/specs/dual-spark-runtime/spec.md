## Purpose

为 RelicScope AI 定义两台 NVIDIA DGX Spark 在受控私有网络中的可配置协同运行契约，使多模态感知与证据应用能够作为独立服务安全通信、持续健康检查，并在节点或模型不可用时透明降级而不外泄数据。

## ADDED Requirements

### Requirement: 双机采用独立服务协同拓扑
系统 SHALL 将双 Spark 运行定义为应用层独立服务协同：默认由 Spark A 承担多模态感知、向量化与检索计算，由 Spark B 承担应用接口、知识与证据服务、检测编排以及可选推理服务。节点间 SHALL 通过受控的服务请求交换最小必要数据；系统 MUST NOT 将该默认拓扑宣称为张量并行，也不得将两台设备的内存描述为共享内存池。

#### Scenario: 默认双机启动成功
- **WHEN** Spark A 与 Spark B 按默认角色配置启动且所有必需服务通过就绪检查
- **THEN** 应用能够通过独立端点调用感知服务和可选推理服务，并在运行信息中明确显示各节点角色及“独立服务协同”模式

#### Scenario: 查看运行拓扑说明
- **WHEN** 用户查看系统状态、部署信息或演示说明
- **THEN** 系统将当前模式标识为应用层双节点协同，不显示张量并行、跨机统一显存或其他不符合实际部署的表述

### Requirement: 逻辑角色必须可配置
系统 SHALL 允许通过部署配置指定应用、感知、检索、证据存储和推理等逻辑角色所在节点，以及相应服务地址、端口、模型标识和启用状态。角色调整 MUST 不要求修改业务代码，并须在启动时检测缺失、重复或冲突配置。

#### Scenario: 调换非持久计算角色
- **WHEN** 操作者将感知或推理角色从一台 Spark 重新配置到另一台具备相应能力的 Spark
- **THEN** 系统根据新配置发现服务并报告实际角色映射，无需改变客户端工作流或业务代码

#### Scenario: 角色配置发生冲突
- **WHEN** 配置把唯一持久写入角色同时声明在两个没有一致性保障的节点上
- **THEN** 系统拒绝进入就绪状态，指出冲突角色和修正要求，不得接受业务写入

### Requirement: 节点通信限制在受信私网
系统 MUST 仅允许在明确配置的受信私网地址和节点身份之间进行跨节点业务通信。默认配置 SHALL 不把模型、检索、证据存储、集群管理或调试端点暴露到公网；面向演示客户端的访问必须经过单一受控应用入口。

#### Scenario: 受信节点发起服务调用
- **WHEN** 已配置的 Spark B 通过受信私网地址调用 Spark A 的感知服务
- **THEN** 请求能够到达目标服务，且服务响应只返回完成当前工作流所需的数据

#### Scenario: 非受信来源访问内部端点
- **WHEN** 非允许地址或非允许节点身份尝试访问模型、检索、证据存储或管理端点
- **THEN** 系统拒绝连接或请求，不返回模型信息、知识内容、器物数据或运行细节

### Requirement: 跨节点 API 必须认证
所有跨节点应用级 API 请求 MUST 携带有效的服务凭据，并且不同环境 SHALL 使用可轮换的非默认 API key 或等效身份凭据。系统不得在源代码、公开配置、接口响应或普通日志中暴露凭据；缺失、无效或已撤销凭据的请求必须被拒绝。

#### Scenario: 使用有效 API key 调用
- **WHEN** 受信节点使用当前有效的服务 API key 请求已授权能力
- **THEN** 服务处理请求并在审计记录中保存不含密钥明文的调用主体和结果状态

#### Scenario: 使用无效 API key 调用
- **WHEN** 请求未携带 API key、使用示例默认值、密钥错误或密钥已撤销
- **THEN** 服务拒绝请求，不执行模型或数据操作，并记录不包含密钥值的认证失败事件

### Requirement: 每项服务具有存活与就绪状态
每个可部署服务 SHALL 提供可机器验证的存活和就绪状态。就绪状态 MUST 反映其必需模型、知识版本、存储连接或设备适配器是否真正可用；应用 SHALL 在调用前检查或持续跟踪就绪状态，并向用户显示节点、逻辑角色、服务状态、模型标识及最近检查时间。

#### Scenario: 进程存活但模型未就绪
- **WHEN** 感知服务进程可以响应但模型权重仍在加载或模型初始化失败
- **THEN** 存活检查可以成功而就绪检查必须失败，应用不得把该服务显示为可正常推理

#### Scenario: 服务恢复就绪
- **WHEN** 先前不可用的服务完成模型加载并通过自检
- **THEN** 系统更新其就绪状态和模型标识，后续新请求可以恢复路由到该服务

### Requirement: 双机故障必须触发可见降级
当任一远程感知、检索或推理服务超时、失联或未就绪时，系统 SHALL 在有安全本地替代能力的情况下继续核心演示流程，并明确标记所用降级路径、缺失能力和结果限制。系统 MUST NOT 将确定性回退、缓存结果或缺失模型的执行显示为完整双机 AI 运行。

#### Scenario: Spark A 感知服务失联
- **WHEN** Spark B 在规定超时内无法访问 Spark A 的感知服务
- **THEN** 应用切换到允许的确定性本地观察或仅记录输入的降级路径，显示 Spark A 不可用，并保持科学结论为保守状态

#### Scenario: 可选推理服务失联
- **WHEN** 证据与检测流程可用但可选报告推理服务不可达
- **THEN** 系统继续生成结构化确定性报告或报告骨架，标明未使用推理模型，不得阻断已有证据的查看与导出

### Requirement: 单台 Spark 支持核心演示模式
系统 SHALL 支持通过角色配置在单台可用 Spark 上运行核心演示能力，并允许关闭超出单机资源或当前环境能力的可选模型服务。单机模式 MUST 显示其实际角色、禁用能力、资源限制和降级状态，且不得伪装为双机运行。

#### Scenario: 以单机配置启动
- **WHEN** 只有一台 Spark 可用且操作者选择单机演示配置
- **THEN** 系统在该节点启动核心应用与允许的本地能力，禁用或降级可选服务，并在界面及运行状态中标识“单机降级模式”

#### Scenario: 单机资源不足以加载可选模型
- **WHEN** 单机启动检查发现剩余资源不足以安全加载可选推理模型
- **THEN** 系统保持核心应用可用、跳过可选模型并说明资源原因，不得通过不受控的外部模型代替

### Requirement: 运行数据不得外泄
系统 MUST 默认禁止在运行期将器物图像、检测原始数据、知识库正文、检索查询、证据图、报告内容、访问凭据或可识别会话信息发送到公网或未批准的外部端点。模型和容器准备阶段的下载行为 SHALL 与业务运行数据流分离，且任何明确允许的外部连接都不得携带器物或知识内容。

#### Scenario: 离线双机执行完整流程
- **WHEN** 容器、模型和知识依赖已预先缓存且运行环境断开公网
- **THEN** 两台 Spark 能够通过私网完成演示流程，不产生对公网服务的业务请求

#### Scenario: 配置包含未批准外部推理端点
- **WHEN** 运行配置将感知、检索或推理服务指向不在允许私网范围内的地址
- **THEN** 系统拒绝该配置或保持对应能力禁用，并明确报告数据边界违规风险

### Requirement: 运行记录可证明实际执行位置
系统 SHALL 为每次跨节点任务记录会话标识、逻辑角色、节点标识、服务版本、模型标识、请求哈希、响应哈希、耗时、健康状态和降级状态。运行记录 MUST 足以区分真实模型调用、确定性本地计算、缓存响应和演示回放，同时不得包含 API key、访问令牌或完整原始图像字节。

#### Scenario: 审核双机调用链
- **WHEN** 审核者查看一次从感知到证据报告的演示会话
- **THEN** 系统能够展示每一步实际运行的节点、角色、模型或回退类型及输入输出哈希，并证明是否发生降级

#### Scenario: 导出运行日志
- **WHEN** 操作者导出用于演示复核的运行日志
- **THEN** 导出内容保留执行可追溯信息，同时移除服务密钥、下载令牌和完整原始媒体载荷
