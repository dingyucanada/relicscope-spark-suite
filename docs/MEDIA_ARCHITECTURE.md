# 图片 / 视频科学观察架构｜v1.1.0

## 1. 产品入口

v1.1.0 把最容易理解、也最接近真实使用方式的入口放到首位：提交瓷器照片或环绕视频，系统先判断素材是否足以观察，再输出可见特征、局部候选、对象科学指纹、参考资料、证据状态和下一步采集建议。

这条链路服务两个层次：

- 收藏人士看到的是清楚的观察结果、证据缺口和下一步建议；
- 专家与机构可以继续追溯到原始文件哈希、帧时间戳、质量门控、模型版本、知识引用、证据关系和审计链。

系统描述科学观察与证据状态，不输出真伪、确定年代、作者、窑口、价格、文物定级或法律鉴定结论。

## 2. 产品层级与当前落点

| 产品层级 | 长期职责 | v1.1.0 软件落点 |
|---|---|---|
| RelicScope Vault V1 | 受控光照、几何、相机和未来传感器的一体化古陶瓷采集样机 | 提供标准采集协议、区域和媒体元数据；当前不声称 Vault 机械与传感器已实装 |
| RelicScope Edge | 本地感知、质量门控、指纹、模型推理和仪器适配 | Spark A 处理有限代表帧的可选 VLM / 嵌入；确定性质量与指纹可降级运行 |
| RelicScope Evidence | 会话、知识、Scientific Evidence Graph、不确定性、审计和报告 | Spark B 为唯一持久写入节点与浏览器入口 |
| RelicScope Knowledge | Gold Dataset、Counterfeit Corpus、文献、标准与专家知识 | 当前只使用版本化、带来源的本地演示资料；正式数据资产需机构合作建设 |
| RelicScope Network | 专家复核、数字护照、机构协作与跨时点验证 | 当前预留报告和对象指纹导出，不实现跨机构生产网络 |

## 3. 媒体分析流水线

```text
原始照片 / 视频
       │ 服务端格式验证、大小限制、SHA-256
       ▼
原始媒体登记（RAW_CAPTURE / USER_SUPPLIED）
       │
       ├─ 图片：直接进入质量门控
       │
       └─ 视频：有限时间采样
                    ├─ 低质量帧：保留记录，不进入有效观察
                    ├─ 近重复帧：保留来源，减少重复推理
                    └─ 代表帧：覆盖不同时间与视角
                              │
                              ▼
               可见特征 / 候选区域 / 视觉指纹
                              │ 可选本地 VLM 与嵌入
                              ▼
                  版本化本地知识与精确引用
                              │
                              ▼
          Scientific Evidence Graph + 四态证据关系
                              │
                              ▼
             Next Best Observation + JSON / HTML 报告
```

视频优先复用浏览器原生 HTML5 Media 与 Canvas 进行有限抽帧，避免第一版增加独立视频编解码服务。浏览器提供时间戳和像素帧，Spark B 重新解码、计算帧哈希和质量结果。原视频未成功登记时，任何预览帧都不能被描述为“已审计的原始视频证据”。

## 4. 质量、去重与代表帧

逐帧质量至少覆盖分辨率、曝光、黑白截断、清晰度和动态范围。系统报告：

- 实际采样帧数；
- 通过与未通过质量门控的数量和原因；
- 被判定为近重复的帧；
- 进入后续分析的代表帧及时间戳；
- 当前媒体未覆盖的器物区域。

代表帧选择同时考虑质量、时间分布和视觉新颖度。未被采样的时间段、模糊区域或严重反光区域必须进入局限说明，不能被描述为已检查。

## 5. 对象科学指纹

对象科学指纹用于同一对象复核、数据关联和相似检索，不是防伪证书或真伪结论。v1.1.0 指纹由以下可追溯成分构成：

- 原始媒体 SHA-256 清单；
- 代表帧 SHA-256 与算法版本；
- 可复算视觉指纹及聚合摘要；
- 观察区域、视频时间戳和媒体来源；
- 当前协议、知识和模型版本。

未来 Vault V1 可以在同一结构中加入几何、光谱、元素和内部结构分量。每一分量独立保留模态、校准和质量，不使用一个不透明总分覆盖差异。

### 同区域复拍比较

同一会话可以选择两次同区域、同模态的合格图片，比较视觉指纹、亮度和清晰度差异。结果只有三类：当前采集容差内稳定、可见差异候选、不可比较。视角差异过大或任一输入未通过质量门控时必须拒绝比较。

该能力适合展示入藏基线、运输前后、保存期间或复查时的对象复核价值。它只反映两次采集中的可见差异，不能自动解释为劣化、修复、替换、材料变化或真伪。系统应优先建议在同机位、同焦距、同光照和同色卡条件下复拍。

## 6. 可见观察与候选异常

多帧汇总分为五类：

| 结果 | 含义 |
|---|---|
| 稳定观察 | 在多个合格视角重复出现的可见事实 |
| 局部候选 | 只在特定帧或区域出现，需要复拍或专家确认 |
| 相互矛盾 | 不同帧、不同观察或参考之间不一致 |
| 覆盖缺口 | 器底、口沿内侧、接足、尺度、色彩或候选局部未充分记录 |
| 局限 | 输入质量、模型状态、知识范围及不可见模态边界 |

候选区域或异常分数只表示“值得进一步看”，不能直接解释为修复、伪造、后配、现代材料或年代冲突。

## 7. 本地知识与 Scientific Evidence Graph

知识检索只使用当前允许的本地知识空间。进入报告的知识性陈述绑定实际返回的条目、来源位置、内容哈希和知识版本。相似度只代表当前特征空间中的接近程度，不代表身份、年代或真伪。

Scientific Evidence Graph 至少组织以下节点：`Artifact`、`Claim`、`Region`、`RawMedia`、`Frame`、`QualityGate`、`ModelRun`、`Observation`、`Fingerprint`、`Reference`、`Recommendation` 和 `Report`。质量失败帧保留为采集记录，但不能形成会改变命题的支持或冲突关系。

关键命题使用四态关系：

| 状态 | 解释 |
|---|---|
| `SUPPORT` | 合格证据与命题某一可检验部分一致；不自动形成鉴定结论 |
| `CONFLICT` | 合格证据与命题某一可检验部分不一致；提高复核优先级 |
| `UNCERTAIN` | 数据、质量或参考范围不足；保留不确定性 |
| `ESCALATE` | 当前能力不足，需要补拍、专家、真实仪器或实验室 |

四态描述“证据如何影响一个命题”，不代表对象的四类最终标签。不同证据冲突时分别保留，不以平均分隐藏分歧。

## 8. Next Best Observation

系统先建议不增加器物物理暴露的低风险动作：

1. 补拍器底、口沿内外、接足和候选局部；
2. 加入比例尺、色卡、固定距离或标准背景；
3. 改善对焦、降低眩光、增加受控侧光或交叉偏振；
4. 对跨帧矛盾区域进行同角度复拍；
5. 可见光无法回答时，再建议 UV/NIR/RTI、3D、Raman、XRF、HSI、X-ray/CT 或 TL。

每项建议说明目标缺口、目标区域、预期信息、最低质量要求、风险/取样边界和当前是否可执行。没有真实设备时只显示 `RECOMMENDED/PLANNED`，不调用合成数据冒充执行。

## 9. 科学检测能力矩阵

| 模态 | 主要信息 | 当前软件状态 | 不能从 RGB 替代得到的内容 |
|---|---|---|---|
| RGB 图片 / 视频 | 器形、纹饰、釉面可见状态、表面候选、拍摄覆盖 | `IMPLEMENTED / LOCAL ACCEPTED`；受输入质量限制，双 Spark/VLM 待上机 | 元素、分子、内部结构、绝对年代 |
| UV / NIR / 偏振 / RTI | 荧光、浅层差异、反射与微表面形貌 | `PROTOCOL / ADAPTER_READY` | 需对应受控采集，不能由普通照片补算 |
| 3D / Open3D | 几何、尺寸、形变、断面与配准 | `ADAPTER_READY` | 需真实深度/扫描数据 |
| Raman / XRF / HSI | 分子、元素与光谱反射信息 | 回放仅 `DEMO/SYNTHETIC`；真实接入待设备验收 | 需真实谱线、校准和参考物 |
| X-ray / CT | 内部结构、接合、空腔与隐藏修复 | `PHASE_2` / 外部实验室 | 需真实辐射成像 |
| TL | 与陶瓷烧成年代相关的实验室测量 | `PHASE_2` / 取样实验室 | 需规范取样与实验室流程 |

## 10. 双 Spark 计算分工

```text
受控浏览器
  │ 原始媒体 / 抽帧
  ▼
Spark B · 媒体登记 / 会话 / 知识 / 证据 / 审计 / 报告
  │ 仅有限代表帧 + 受限任务 + 服务密钥
  ▼
Spark A · 本地 VLM / 嵌入 / 感知计算
```

Spark B 保存原始媒体和全部证据状态；Spark A 只接收完成当前任务所需的有限代表帧。每次跨节点调用记录节点、模型、请求/响应哈希、耗时和降级状态。Spark A 失联时，媒体登记、确定性质量、指纹、知识、证据和报告继续运行，并明确显示模型观察缺失。

## 11. 报告结构

JSON 与 HTML 使用相同骨架：

1. 报告、会话、协议和免责声明；
2. 对象及送检声明；
3. 原始图片/视频清单、来源与 SHA-256；
4. 视频采样、时间戳、质量、去重和代表帧；
5. 对象科学指纹；
6. 可见观察、候选区域、跨帧稳定性与覆盖缺口；
7. 本地知识引用；
8. Scientific Evidence Graph 与四态关系；
9. 不确定性、冲突和拒绝判断；
10. Next Best Observation 与分级检测建议；
11. 模型/算法运行、降级状态及能力矩阵；
12. 审计链验证、报告哈希与完整性边界。

HTML 面向阅读和展示，JSON 面向后续机构系统、数字护照和科研分析。两者均不包含服务密钥或不必要的原始媒体载荷。

## 12. 成熟框架路线

- 当前本地模型路径：NVIDIA vLLM + OpenAI-compatible API。
- 视频采集与显示：浏览器 HTML5 Media / Canvas。
- 实时相机与多路流：设备确定后评估 NVIDIA Holoscan / Sensor Bridge 与 DeepStream Service Maker Python（Flow/Pipeline API）。
- 3D：真实扫描数据到位后评估 Open3D。
- Raman、XRF、HSI：分别评估 RamanSPy、PyMca、Spectral Python；库不替代校准和专家协议。
- 大规模多模态知识：数据规模、授权和硬件验证满足后评估 NeMo Retriever、NIM、cuVS / Milvus。
- 表面异常：仅在有合法训练集和独立验证集时评估 anomalib；热图保持候选含义。

任何组件只有通过 ARM64、版本、许可证、真实格式、资源占用、故障降级和端到端验收后，才从路线图状态转为已集成能力。
