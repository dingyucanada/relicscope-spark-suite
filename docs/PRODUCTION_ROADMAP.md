# 从可运行 Demo 到正式部署：必要开发路线

## 1. 当前基线

v1.0.0 已证明会话、知识、主动检测、证据和报告闭环；v1.1.0 把图片/视频登记、多帧质量与代表帧、对象科学指纹、Next Best Observation 和媒体结构化报告组成面向观众的主入口。核心流程在模型不可用时仍能显式降级。

当前科学测量仍为 `DEMO/SYNTHETIC` 回放；双 Spark 的镜像、GPU、私网、断网和性能尚待目标设备验收。正式产品的下一阶段重点是把真实采集、校准、参考样本、专家复核和机构治理接到同一控制面。

## 2. P0：双 Spark 现场部署与演示冻结

目标周期：取得设备权限后的 1–3 天。

| 工作 | 完成标准 |
|---|---|
| Spark A / B 固定私网与模型预缓存 | 两节点 health 返回实际节点、模型、镜像和服务版本；错误 key 被拒绝 |
| 图片 / 视频主 Demo | 原始媒体服务端哈希、质量/代表帧、本地引用、证据图、建议和 JSON/HTML 报告可复演 |
| 断公网运行 | 完整 P01 和报告不产生公网业务流量；缺少缓存时明确失败 |
| 故障降级 | Spark A 停机后 Spark B 保留会话、知识、证据与报告，并显著显示视觉降级 |
| 持久性与恢复 | 容器重启后同一 session 可读取；备份恢复到新目录并通过审计链验证 |
| 演示冻结 | 保存发布包 SHA-256、配置快照、模型 revision、最终会话和报告 hash |

Spark A 继续承担视觉模型与可选嵌入；Spark B 继续承担唯一入口、知识、P01、证据、审计和报告。两个独立服务的拓扑优先保证稳定性。跨机张量并行保留为需要单个大模型时的可选运行模式，不影响核心科学工作流。

## 3. P1：首批真实科学数据

目标周期：2–6 周，取决于设备和参考样本。

建议按以下顺序接入：

1. Vault V1 受控 RGB / UV / NIR 相机与色卡、尺度、白平衡和曝光协议；文件型视频先沿用浏览器有限抽帧，实时传感器阶段再引入 Holoscan / Sensor Bridge；
2. Raman 文件导入，以 RamanSPy 处理并完整记录参数、参考谱与激光条件；
3. XRF 文件导入，以 PyMca 处理谱峰和拟合结果，并记录校准、基体与层结构边界；
4. HSI 立方体导入，以 Spectral Python 处理白/暗参考、波段和空间配准；
5. RTI / 多光照查看与三维扫描，以 OpenLIME、Open3D 或经批准的等价组件验证。

每个适配器输出统一 `ScientificResultEnvelope`，并完成：真实文件样例、校准引用、稳定错误码、重复性、跨批次偏移、区域映射、故障样本和撤销/重跑测试。应用先记录实际暴露，再执行质量门控；质量失败的数据保留在审计链中且不更新科学命题。

## 4. P2：数据与模型评测体系

目标周期：6–16 周，随机构合作持续扩展。

- 建立 Gold Dataset：器物类别、材质、器形、区域、采集协议、仪器、参考物、专家结论和授权完整分层；
- 建立 Counterfeit Corpus：来源合法、争议状态清楚、证据和反例均可追溯；
- 固定训练、验证、外部留出和时间外测试，禁止同一器物或同源拍摄跨集合泄漏；
- 对视觉观察、相似检索、异常候选、光谱模型、质量门控和拒绝判断分别评测；
- 报告灵敏度、特异度、校准误差、覆盖率、拒绝率、跨设备性能和专家复核一致性；
- anomalib 只在合法且分层的“正常参考”数据上评估，热图始终显示为异常候选。

当文献和参考样本规模确实超过轻量索引能力后，再引入 NeMo Retriever 和 cuVS/Milvus。迁移必须保持来源定位、知识版本、撤权和报告可复现。

## 5. P3：生产安全与机构签署

正式机构运行前必须完成：

- Spark B 前置 TLS/mTLS 反向代理、机构 SSO、用户级 RBAC、速率限制和会话超时；
- 服务独立身份和短期凭据，替换 Demo 的共享环境 key；
- 数据分类、加密备份、保留/删除政策、灾备演练和安全日志；
- 容器 digest、SBOM、签名、漏洞扫描与受控升级；
- 报告机构数字签章、可信时间戳、签署权限与撤销机制；
- 真实激光、辐射或取样设备的人员授权、硬件联锁和站点安全程序；
- 盲测、专家复核、版本变更再验证和异常事件处置。

Holoscan / Sensor Bridge 与 DeepStream Service Maker Python 在真实实时相机、采集卡和多路流需求明确后接入。NVIDIA 已提供 DGX Spark 的 Holoscan/Sensor Bridge 主机支持说明，DeepStream Service Maker Python 提供 Flow/Pipeline API；这些兼容性信息只说明路线可行，不等于 RelicScope 已集成。引入前仍需验证版本、驱动、时间同步、背压、丢帧、设备断连和安全停止。

## 6. 能力展示的最低证据包

对投资人、收藏界和合作机构展示时，建议同时准备：

1. 七分钟图片/视频主闭环，展示原始哈希、质量、代表帧、指纹、引用、证据图、建议和报告；
2. 五分钟 P01 闭环，展示失败数据被拒绝、风险仍结算和主动重规划；
3. 一次真实 RGB 采集与一次真实 Raman / XRF / HSI 文件导入；
4. 一份带输入哈希、软件版本、校准引用、证据图和审计验证的报告；
5. Spark A 断连后的可见降级与恢复；
6. 两台 Spark 的实际节点、模型、延迟、显存和私网流量记录；
7. 科学适用范围、拒绝条件和下一步专家路径。

这些证据能够说明系统具备工程能力与科学治理能力，同时保留真实鉴定所需的实验室、专家和机构边界。
