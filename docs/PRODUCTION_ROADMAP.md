# RelicScope V2：从可复现软件到现场系统

> 适用对象：项目负责人、工程团队、客户技术团队与合作机构
> 当前状态：代码、配置和自动化测试已经验证；目标 DGX Spark、Android Scout 与真实业务数据尚待现场验收
> 核心原则：一台 Spark 完成完整闭环，第二台按业务需要扩展

## 1. 路线目标

V2 首先交付一套稳定的本地 AI 基础设施：Scout 在现场完成规范拍摄和安全上传，DGX Spark 在本地完成任务管理、多模态观察与结构化结果。系统必须在没有艺术品参考库、没有第二台 Spark、没有公网连接的情况下，仍能完成基础流程并清楚说明能力边界。

```text
Android Scout
拍摄引导 · 端侧质检 · 离线队列
        │ HTTPS / 每设备独立凭据
        ▼
主 DGX Spark
接入网关 · 本地存储 · 持久任务 · NVIDIA NIM · 结构化结果
        │
        └── 可选第二台 Spark
            备用 · A/B 评测 · 视频候选 · 微调 · 批处理
```

本路线不把生成式模型输出包装成鉴定结论，也不把尚未获得授权的数据资产写成既有能力。

## 2. 状态口径

| 状态 | 含义 | 当前结论 |
|---|---|---|
| `CODE_VERIFIED` | 软件逻辑、配置检查、测试和发布边界已在开发环境验证 | V2 当前达到 |
| `DEPLOYMENT_READY` | 具备面向目标设备的安装、离线准备、启停、健康检查和验收路径 | 交付包已准备，仍需在客户设备执行 |
| `HARDWARE_VERIFIED` | 固定提交、镜像、NIM profile 和配置已经在指定 DGX Spark 留下可复核证据 | 尚未达到 |
| `PILOT_ACCEPTED` | 客户认可稳定性、性能、安全边界和业务流程 | 尚未达到 |
| `DOMAIN_VALIDATED` | 领域任务在授权、独立且专家复核的数据上达到事先约定指标 | 不属于当前代码验收结论 |

通过自动化测试不代表模型已经在客户 Spark 上运行，也不代表系统具备古陶瓷真伪、年代、窑口或价值判断能力。

## 3. P0：第一台 Spark 现场验收

优先级最高。建议在取得设备与网络权限后连续完成，不与第二台机器或参考库建设绑定。

| 工作 | 完成标准 |
|---|---|
| 冻结运行基线 | 记录 Git commit、DGX OS、驱动、容器 digest、Qwen3.6 NIM profile、配置摘要与许可证复核结果 |
| 单机完整闭环 | Scout 配对、图片上传、质量门控、持久任务、本地 NIM 推理、结构化结果与补拍建议全部成功 |
| 模型运行证明 | 保存 served model、profile ID、容器 digest、请求 ID、输入/输出哈希、延迟和完成时间 |
| 本地与离线边界 | NIM 模型端口不暴露；准备完成后断公网仍可启动和完成任务；缺少缓存时失败关闭 |
| 性能与稳定性 | 测量 1/3/5 张图片的冷/热启动、p50/p95、峰值统一内存；连续任务不发生 OOM 或隐式降级 |
| 故障恢复 | 验证 Scout 断网续传、应用和模型重启、失败重试、低磁盘拒绝、设备撤销、备份恢复 |
| Android 真机 | 在客户目标机型验证 CameraX、后台队列、本地 CA/机构证书和 Wi-Fi/有线网络路径 |

第一阶段使用 Qwen3.6-35B-A3B 的 DGX Spark 专用 NVIDIA VLM NIM。只启用图片输入、结构化 JSON、单并发和明确的超时/重试。视频路径需要额外 ARM64 FFmpeg 依赖和资源验收，不能影响首个稳定版本。

## 4. P1：模型与数据的受控评测

现场基础设施稳定后，再评估模型质量和领域增益。

1. 固定同一批输入、视角顺序、提示词、JSON schema 和评分表；
2. 以 Qwen3.6 NIM 作为生产试运行基线；
3. 顺序测试 Qwen3.8 等中文质量候选；
4. 仅在视频业务明确后测试 Nemotron 3 Nano Omni；
5. 同时评价中文可见事实、结构化输出、拒绝边界、延迟、内存和故障恢复；
6. 由专家盲评决定领域质量，机器分数只提供工程证据。

客户授权的参考图片、负向案例或知识材料先作为独立数据包导入，不进入公开仓库。数据量较小时优先使用可复算的确定性索引；只有当检索规模和性能证明确有必要时，再引入 GPU 向量检索或完整 RAG 组件。

微调或 LoRA 只在任务定义、授权训练数据、独立测试集和基线错误分析均已具备时开展。目标应是可测量的窄任务，例如视角识别、器型字段抽取或专业术语规范化，不能用微调掩盖拍摄质量或数据治理问题。

## 5. P2：第二台 Spark 的弹性使用

第二台 Spark 不设置永久固定职责，也不作为主系统启动条件。优先根据实际瓶颈选择一种用途：

- 运行与主机相同的冻结版本，作为人工切换备用；
- 承载候选模型、视频模型或 A/B 评测，避免影响现场服务；
- 执行 LoRA/PEFT、批量评测和离线索引；
- 在业务量明确后，承担独立队列或批处理容量；
- 只有单机无法满足经过测量的模型容量或性能门槛时，才评估 ConnectX-7、Ray/NCCL 与分布式推理。

双机互联不等于共享显存，也不能宣传为自动形成一张 256GB GPU。任何跨机方案都必须新增网络、同步、故障、恢复和性能验收。

## 6. P3：知识、Agent 与报告能力

基础链路稳定后，可按业务价值逐项启用：

- 客户授权的参考样本包、来源和许可管理；
- 带出处定位、版本和撤权能力的受控知识检索；
- 同一实物候选、相关参考和负向相似信号的分离呈现；
- 受限 Agent 工具，用于补拍建议、资料检索或后续仪器流程编排；
- Scientific Evidence Graph、不确定性状态和可追溯报告；
- 专家复核、报告批准、机构签章和可信时间戳。

Agent 不能自行改变结论状态，也不能绕过设备认证、质量门控、人工审批或仪器安全联锁。没有授权参考库时，系统必须明确返回“未使用参考库”，不能用通用知识补齐不存在的证据。

## 7. P4：真实科学仪器与标准化

Raman、XRF、HSI、RTI、X-ray、CT、TL 等能力属于后续科学验证阶段。接入顺序由客户场景、设备可得性、安全要求和参考样本决定。每个适配器至少要完成：

- 原始文件、仪器型号、参数、操作者、时间与区域定位；
- 校准引用、参考物、处理软件及参数版本；
- 重复性、跨批次偏移、故障样本和拒绝条件；
- 与对象、采集区域、命题、报告和审计记录的关联；
- 激光、辐射或取样操作的人员授权、硬件联锁和站点程序。

真实测量接入前，现有回放或合成数据只能标记为 `DEMO/SYNTHETIC`。视觉模型不能生成或替代任何光谱、成分、断层或热释光测量。

## 8. P5：生产治理与机构合作

正式机构运行前还需完成：

- 机构 CA、SSO/RBAC、设备生命周期、速率限制和会话策略；
- 数据分类、保留与销毁、加密备份、恢复演练和安全事件响应；
- 镜像 digest、SBOM、签名、漏洞扫描和受控升级；
- 真实数据的授权、权属、撤权、用途限制和跨机构协议；
- 报告签署权限、可信时间戳、版本变更再验证和异常事件处置；
- 领域指标、外部留出集、专家一致性与标准化合作。

## 9. 对外展示的最低证据包

一次严肃的演示应以真实运行链为中心：

1. Scout 多视角采集、断网保存与恢复上传；
2. 单台 Spark 的本地 NIM 推理与结构化结果；
3. 模型身份、输入/输出哈希和任务阶段记录；
4. 低质量图片的拒绝与补拍，而非强行生成结论；
5. 设备撤销、模型不可用、低磁盘或重启后的可见行为；
6. 一份明确写出证据来源、限制和下一步的报告；
7. 如使用第二台 Spark，展示可测量的备用、A/B 或批处理价值。

对外材料应分别标记 `CODE_VERIFIED`、`HARDWARE_VERIFIED` 和 `DOMAIN_VALIDATED`，并引用相应证据。这样既能展示 NVIDIA 本地 AI 基础设施的工程价值，也能保护项目的科学可信度。
