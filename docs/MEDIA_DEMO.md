# 图片 / 视频结构化报告 Demo 操作手册｜v1.1.0

## 1. 演示结果

主路径为：

```text
上传瓷器图片或视频
→ 质量门控与代表帧
→ 可见观察与对象科学指纹
→ 本地知识引用
→ Scientific Evidence Graph
→ Next Best Observation
→ JSON / HTML 结构化报告
```

建议把这条媒体路径作为主 Demo，把 P01 主动检测回放作为“从可见观察继续走向真实多模态检测”的第二幕。这样观众先看到熟悉的输入，再看到 RelicScope 的技术差异：系统知道证据从哪里来、质量是否足够、当前不能回答什么，以及下一次应该采集什么。

> **边界**：用户上传的图片和视频属于真实输入；内置知识或仪器回放仍标记 `DEMO/SYNTHETIC`。普通 RGB 媒体不能产生 Raman、XRF、HSI、X-ray、CT 或 TL 测量值。输出不构成真伪、年代、作者、窑口、价格、文物定级或法律鉴定结论。

## 2. 演示前准备

准备一件瓷器的以下素材：

- 1–4 张清晰照片：正面、背面、器底、口沿或重点局部；
- 或一段 10–45 秒缓慢环绕视频；
- 尽量使用固定背景、均匀光照，减少镜面反光；
- 画面中加入比例尺或已知尺寸物；
- 不要在视频中突然快速摇镜、持续变焦或让手遮挡器物。

正式活动前使用同一台浏览器完成一次彩排，记录文件大小、分析时长和报告是否能够下载。若现场网络不稳定，系统应在本地离线模式运行，素材预先复制到演示电脑，不依赖云盘或公网。

## 3. 图片流程

1. 打开 Spark B 的浏览器入口并确认顶部显示实际运行模式、节点和 `DEMO/SYNTHETIC` 边界。
2. 创建器物会话，填写对象名称和待验证声明。声明是送检方提供的待验证信息，不是系统结论。
3. 选择“图片”，提交一张或多张瓷器照片，并关联器物区域。
4. 查看每张图片的原始 SHA-256、分辨率、曝光、清晰度、动态范围和质量门控。
5. 查看通过门控的可见观察、候选区域、代表图像和对象科学指纹。
6. 打开本地知识引用，确认每项引用显示来源、位置、版本和演示/审核状态。
7. 查看证据关系、当前不确定性和 Next Best Observation。
8. 生成报告，分别下载 JSON 和 HTML。

低质量图片仍保留为采集记录，但不应被显示为有效科学证据。模型不可用时，界面应清楚显示降级，并继续完成确定性质量、指纹、知识、证据图与报告。

## 4. 视频流程

1. 创建新会话或在当前会话中选择“视频”。
2. 选择本地 MP4、MOV 或 WebM 等当前界面声明支持的格式；以实际文件选择器和服务端验证结果为准。
3. 先完成原视频登记。确认界面返回视频标识、字节数、媒体类型和服务端 SHA-256。
4. 浏览器按有限时间点抽帧。等待时间轴显示采样点、通过/失败、近重复和代表帧状态。
5. 查看代表帧时间戳和原因：质量较高、覆盖新的视角或补充新的局部信息。
6. 查看多帧汇总：稳定观察、局部候选、相互矛盾、覆盖缺口和局限。
7. 查看对象科学指纹、本地知识引用、证据图与下一步采集建议。
8. 下载 JSON / HTML 报告，确认报告列出原视频哈希、所有证据帧时间戳和能力边界。

如果原视频登记失败，浏览器预览或抽帧不得被当作“已审计视频”。如果所有帧均未通过门控，系统应输出重新采集建议，而不是勉强生成可靠性外观结论。

## 5. 同区域复拍比较

1. 在同一会话上传两张同区域、同模态图片，分别作为基线和复拍。
2. 两张图片都通过质量门控后，选择“比较”。
3. 查看结果属于“采集容差内稳定”“可见差异候选”或“不可比较”。
4. 若视角、光照或清晰度差异过大，系统应拒绝过度解释并建议标准条件复拍。
5. 在证据图和报告中核对两份原始哈希、比较指标、结论边界和下一步建议。

这项能力体现入藏、运输、保险、保存监测和跨时点对象复核价值。它只比较可见差异，不能解释为劣化、修复、替换、材料变化或真伪。

## 6. 建议展示的七个核心功能

### A. 可验证输入

重点展示原始媒体 SHA-256、帧时间戳和派生关系。讲解：“先确认分析的究竟是哪份数据，后续每个结论才能复核。”

### B. 质量先于模型

展示一张模糊或反光图片被门控拦截。讲解：“模型能回答，不等于这份素材足以支持科学观察。RelicScope 先判断数据是否合格。”

### C. 多帧收敛

展示视频帧如何被分为低质量、近重复和代表帧。讲解：“系统不把整段视频无界交给模型，而是保留时间来源，用高质量的新视角组成可复核观察集。”

### D. 对象科学指纹

展示原始媒体、代表帧和算法版本组成的指纹。讲解：“这是一份可复算的对象技术身份，未来可以叠加三维、光谱、元素和内部结构；当前不把视觉指纹说成防伪证书。”

### E. Scientific Evidence Graph

从一项观察点回原图或视频时间戳，再连接到模型运行、本地引用、待验证命题和报告。讲解：“每个陈述都知道来自哪里、通过了什么质量门、支持还是冲突，以及有哪些局限。”

### F. Next Best Observation

展示系统先建议补拍器底、口沿、接足、比例尺或降低眩光，再在必要时建议 UV/NIR/RTI、Raman、XRF、HSI、X-ray/CT 或 TL。讲解：“AI 的价值不只在解释已有素材，也在决定下一份最有价值、且安全的数据是什么。”

### G. 同区域复拍比较

展示一次基线—复拍比较。讲解：“高价值对象需要跨时间复核。系统先判断两次采集是否可比，再提示可见差异候选；采集条件不足时拒绝解释，并要求标准化复拍。”

## 7. 七分钟演示脚本

| 时间 | 操作 | 建议讲解 |
|---|---|---|
| 0:00–0:40 | 打开首页与双节点状态 | “数据留在本地。Spark A 负责多模态计算，Spark B 负责知识、证据、审计和报告；两台设备是同一套私有系统。” |
| 0:40–1:30 | 建档并上传图片或视频 | “每个原始文件先做服务端哈希登记。我们分析的是明确的一份数据，而不是一个无法追溯的聊天附件。” |
| 1:30–2:20 | 展示质量门控与代表帧 | “低质量和重复帧不会被悄悄混进结论。报告保留时间戳，也把没有覆盖的角度写出来。” |
| 2:20–3:00 | 展示可见观察、候选区域和指纹 | “系统描述可见事实和待复核候选。对象指纹用于复核与关联，不等同于真伪判断。” |
| 3:00–3:30 | 展示基线—复拍比较 | “先判断两次采集是否可比，再提示差异候选。可见变化不自动等于劣化、修复或替换。” |
| 3:30–4:15 | 打开本地知识引用 | “知识库在本地、版本固定，每一句知识性描述都能回到来源位置。找不到充分参考时，系统会说资料不足。” |
| 4:15–5:05 | 打开证据图和四态关系 | “这里区分支持、冲突、不确定和升级。相互矛盾的证据会被同时保留，不用一个看似精确的总分掩盖。” |
| 5:05–5:55 | 展示 Next Best Observation | “系统先建议低风险补拍；普通照片回答不了材料和内部结构时，才建议相应科学仪器。” |
| 5:55–6:35 | 生成并打开 HTML / JSON 报告 | “给人看的是 HTML，给机构系统和数字护照使用的是 JSON；两者来自同一个证据骨架。” |
| 6:35–7:00 | 切到 P01 回放或能力矩阵 | “今天跑通的是 RGB 媒体与证据软件。Raman、XRF 等回放只证明工作流；真实测量要在设备、校准和专家协议齐备后接入。” |

## 8. 报告检查

如需在浏览器演示前做一次真实媒体烟雾验收，可先从视频导出 3–12 张时间均匀的 JPEG/PNG 帧，再运行：

```bash
python3 scripts/media-smoke.py \
  --image /path/to/baseline.jpg \
  --comparison-image /path/to/recapture.jpg \
  --video /path/to/orbit.mp4 \
  --frames-dir /path/to/extracted-frames \
  --duration-ms 6000 \
  --report-json /tmp/relicscope-media-report.json
```

脚本真实调用当前服务的图像、复拍比较、视频登记、多帧分析、报告和完整性接口；它不会生成或伪装 Raman、XRF、HSI、X-ray、CT 或 TL 测量。

下载后至少核对：

- 原始图片或视频逐项列出 SHA-256；
- 视频具有采样策略、帧时间戳、质量、重复和代表帧说明；
- 模型状态区分实际运行、确定性回退和未启用；
- 知识陈述具有真实返回的本地引用；
- 证据图保留支持、冲突、不确定和升级；
- 报告说明当前不能由 RGB 媒体回答的科学问题；
- Next Best Observation 区分可立即补拍与需要外部设备的建议；
- 审计链验证、尾哈希和报告哈希存在；
- 出现回放或演示资料时，首屏和相关项目显示 `DEMO/SYNTHETIC`。

## 9. 常见现场问题

| 现象 | 处理 |
|---|---|
| 视频不能预览或抽帧 | 换用浏览器支持的 MP4/WebM；不要通过改扩展名伪装格式 |
| 上传被拒绝 | 检查大小、媒体类型、文件是否损坏及环境配置上限 |
| 多数帧模糊 | 重新拍摄：减慢环绕速度、固定曝光、提高照度、减少变焦 |
| 反光导致候选区域过多 | 改变光源角度、使用柔光或交叉偏振，再补拍同一区域 |
| VLM 显示降级 | 检查 Spark A 就绪和私网；仍可继续确定性质量、指纹与报告 |
| 没有知识引用 | 视为知识不足；检查知识版本和检索范围，不用无来源描述补足 |
| 报告为 `REVIEW_REQUIRED` | 这是预期的保守状态；按 Next Best Observation 补采或交由专家 |

## 10. 数据处置

- 原始媒体默认保存在 Spark B 的受控持久目录；先确认磁盘加密、权限、保留期和备份策略。
- 报告分享前检查是否包含送检人、机构、器物来源或其他敏感字段。
- 开放活动使用脱敏样本；不要把服务密钥、HF token、`.env`、原始媒体或完整报告粘贴给外部在线服务。
- 删除或归档真实数据属于机构数据治理操作，不由演示脚本自动执行。
