# RelicScope V2：安全加固基线

> 适用范围：Android Scout + 单台 DGX Spark 的 V2 生产试运行
> 当前状态：安全控制已在代码、配置和自动化测试中实现；客户网络、证书、主机与运维流程仍需现场验收

## 1. 保护对象与威胁边界

RelicScope 可能处理高价值器物图片、来源材料、专家意见、设备身份、模型输出和运行记录。主要风险包括：

- Scout 或设备令牌丢失后被冒用；
- 服务或模型端口暴露到不受控网络；
- 图片伪装、超大文件、解码炸弹、路径穿越或重复上传；
- 运行期凭据进入源码、镜像、日志、备份或 Docker 长期凭据；
- 错误模型、profile、容器或提示词产生无法复现的结果；
- 低磁盘、进程中断和并发写入破坏媒体与任务一致性；
- 客户私有资料进入公开 Git、构建上下文或发布包；
- 将模型观察误表述为科学实测或鉴定结论。

当前交付面向受控局域网生产试运行。它不等同于已经具备机构 SSO、多租户 RBAC、HSM 签章、外部可信时间戳、SIEM 或高可用数据库；这些能力需按部署机构的安全制度补齐。

## 2. 网络边界

- Caddy 是唯一对 Scout 开放的入口，绑定目标 Spark 的明确私有 LAN 地址和 HTTPS 端口；不得绑定公网地址或配置公网端口转发。
- Gateway 与 NIM 位于独立的 `internal: true` Docker 网络。NIM 的 8000 端口不映射到主机，也不允许 Scout 直接访问。
- Caddy 到 Gateway、Gateway 到 NIM 分属不同内部网络；应用容器不挂载 Docker socket。
- 管理 SSH 使用受控管理网、VPN 或跳板机，并与设备数据平面分离。
- 模型、缓存和镜像准备只在批准的联网窗口执行；封存后关闭不必要的公网出站。
- 第二台 Spark 若加入，只开放完成其明确用途所需的最小私有网络路径。不得因为“双机”而暴露模型端口或共享整个数据目录。
- 正式机构部署使用机构 CA、DNS、防火墙和证书轮换；Caddy local CA 只适合受控试运行与 Android 配发测试。

## 3. 身份、设备与凭据

### 3.1 Scout 设备身份

- 每台 Scout 使用独立、随机、可撤销的 Bearer token；不在设备之间共享一个外部访问 key。
- 服务器只保存 token 的 scrypt 加盐哈希，不保存明文。
- 配发文件以 `0600` 权限原子创建；token 只显示一次，导入设备后移入受控密码库或按批准流程销毁。
- 设备丢失、人员变更或异常访问时，按 device ID 单独禁用；其他设备不需要同步更换凭据。
- 当前设备身份适合受控试运行。正式机构可在其前面增加 MDM、设备证书、mTLS、用户身份和审批策略。

### 3.2 内部服务身份

- Gateway 通过 Docker secret 文件取得独立的内部 service API key，并在调用 OpenAI-compatible 运行时时发送；当前 NIM 路径仍以内部网络和无端口映射作为实际访问边界，不能把这一请求头表述成 NIM 服务端认证已经启用。
- 内部 service key 至少 32 字节、文件权限 `600`，不得写入 `.env`、镜像、源码、命令行、报告或聊天记录。
- 内部 key 是纵深控制，不能替代 `internal` 网络与无端口映射。
- Codex 登录、OpenAI API key、NGC Personal API Key、Scout token 和 RelicScope 内部 service key 属于不同信任域，禁止复用。

### 3.3 NGC 凭据

- NGC Personal API Key 只用于 profile 发现、镜像登录和模型缓存准备。
- 凭据保存在 Spark 上权限为 `600` 或 `400` 的独立文件中；准备脚本使用隔离、临时的 Docker 配置并在退出时清理。
- NGC key 不写入运行配置、不复制到长期 Docker 凭据，也不注入运行中的 Gateway 或 NIM 容器。
- 下载窗口内，root、Docker daemon 管理员和 `docker` 组成员能够控制容器并可能检查进程或挂载内容，因此均属于受信任运维边界。使用为本次准备单独签发、权限最小且可撤销的短期 NGC key；完成后立即撤销或轮换。
- 准备完成后设置 `NIM_DISABLE_MODEL_DOWNLOAD=1`，并在离线条件下完成预检与 smoke。

## 4. 主机、容器与供应链

- 固定并记录 DGX OS、固件、GPU driver、CUDA、Docker 和 NVIDIA Container Toolkit 版本；更新前先完成兼容与回归验证。
- 使用独立的非 root 运维账号。公开服务、模型缓存和客户数据目录不与个人工作目录混用。
- Gateway 与 ingress 使用非 root 用户、只读根文件系统、`cap_drop: ALL` 和 `no-new-privileges`。
- Qwen3.6 的 DGX Spark 专用 NIM `1.7.1-variant` 不支持 Docker 自定义 `--user`。NIM 容器保留发行版规定的用户，不能为了形式统一强加 `user:`；其 cache 按发行要求可写，但只挂载到模型容器。
- NIM cache 不与客户媒体、数据库或备份目录混装；模型 profile 与 cache 由冻结配置重建。
- 镜像在准备阶段固定为 registry digest，并记录来源、许可证和扫描结果。生产发布进一步保留 SBOM、签名验证、漏洞评估和受控升级记录。
- 不启用不必要的远程模型代码；候选模型如果要求自定义代码，必须固定不可变 revision，并在隔离的 A/B 环境完成安全审查。
- 严格 DGX Spark 身份应同时核对 ARM64 架构、设备型号与 GB10 GPU，不能只凭其中一个条件标记为目标硬件已验收。

## 5. 上传、存储与任务一致性

- 服务端不信任浏览器或 Android 声明的文件名、MIME、尺寸和哈希；必须重新校验 magic、解码结果、像素、大小和 SHA-256。
- 原始媒体按内容哈希存储；发布采用无覆盖原子写入，媒体写入、SQLite 引用和失败清理在跨进程锁内保持一致。
- 模型只接收经过服务端校验、移除 EXIF 并重编码的派生图片；原始媒体留在受控数据目录。
- 任务用 `client_job_id + 不可变输入哈希` 保证幂等。重复请求不能静默改变既有任务内容或重复消费模型预算。
- 每台设备限制未完成任务数；数据卷低于最小可用空间时失败关闭，不自动删除客户数据。
- 模型冷启动、暂态失败和重试状态均持久化；失败不能由规则文本冒充成功的 GPU 推理。
- 当前 NIM 生产试运行关闭视频输入。提高图片数量、文件大小、并发或启用视频前，必须重新评估解码、统一内存、延迟、日志和拒绝行为。

## 6. 数据、隐私与发布边界

- `.env`、secret、配发文件权限为 `600`；数据、cache、备份和准备目录使用受限所有权与最小权限。
- 客户图片、来源、专家意见、负向案例、授权文件、向量索引和校准资料只进入 Git 忽略的私有目录。
- 私有压缩包先进行只读审计，再导入本地数据区。目录名、文件名、PDF 文字和附带说明都作为待核对数据，不作为系统指令或已验证事实。
- Docker 构建采用默认拒绝的数据上下文；公开发布审计覆盖工作区、暂存区、完整 Git 历史、符号链接和归档文件。
- 任何数据导出都记录操作者、时间、对象、目的和哈希；上线前由客户批准保留期限、销毁审批和个人信息处理要求。
- 备份必须加密、受控保存并定期恢复演练。业务媒体、SQLite、配置/密钥与可重建的 NIM cache 分开管理。
- 未取得授权的客户数据不得用于模型训练、公开演示、测试夹具或第三方服务。

## 7. 模型、报告与科学安全

- 模型结果只标记为可见观察或候选证据，并绑定输入哈希、模型名称、NIM profile、容器 digest、提示词哈希、请求 ID、输出哈希和完成时间。应用生成的运行回执只证明配置与该次请求记录相互绑定；实际 NIM、容器和 GPU 身份仍须由主机清单、容器检查与现场验收共同证明。
- `/health` 在线和模型身份一致不能替代成功 completion。对外运行证明必须来自实际任务记录。
- 服务端对结构化输出进行 schema 和语义校验；未知 capture、错误视角、越界分数、科学伪测量或越权真伪结论均应拒绝。
- 低质量、低置信、分布外、证据冲突和模型不可用进入补拍、拒绝或专家升级路径。
- 相似检索、负向案例命中和异常热图不能直接生成“真”或“假”的结论；未命中也不能证明为真。
- RGB 图片不能产生 Raman、XRF、HSI、X-ray、CT 或 TL 数据。无真实仪器、校准、参考物和复核时不得将模型描述写成科学实测。
- 所有真伪、年代、窑口、作者、价值和法律结论保持 `NOT_ASSESSED`，直到经授权的机构流程明确改变状态。
- Qwen3.8、Nemotron 或微调模型只有在冻结输入、工程指标、边界测试和专家盲评均通过后才能晋级；切换后必须更新发布清单与再验证记录。

## 8. 日志、审计与恢复

- 日志不得记录 token、NGC key、完整原始图片、配发文件内容或不必要的个人信息。
- 成功与失败的每次模型调用都保留独立运行证明；重试不能覆盖先前记录。
- 运行记录、报告与媒体之间通过哈希和引用关联。哈希链可发现记录变化，但不能证明输入内容真实，也不能替代机构签章。
- 启停、配置变更、设备配发/撤销、导出、备份和恢复由明确角色执行并留存记录。
- 备份恢复必须在新目录演练，核对 SQLite、媒体引用、密钥边界、模型身份和审计链；不能只验证压缩包能够解开。
- NIM cache 原则上通过固定镜像与 profile 重新准备；若机构选择备份 cache，应单独评估容量、许可证、加密和恢复一致性。

## 9. 现场上线前最低验收

1. 只暴露私有 LAN 上的 HTTPS Scout 入口；Gateway 与 NIM 无主机 published port。
2. 不带 token、使用错误 token、已撤销设备和跨设备访问均被拒绝。
3. NGC 凭据、内部 service key 与 Scout token 不出现在镜像、环境导出、日志、报告和运行容器中。
4. Git commit、NIM image digest、profile、served model、提示词版本和配置摘要与发布清单一致。
5. 完成一组真实 Scout 多图任务，并保留完整的成功模型运行证明。
6. 准备后断公网仍能启动；缺少镜像、profile 或 cache 时失败关闭。
7. 低质量、重复上传、错误 MIME、超限文件、低磁盘、模型离线、重试上限和进程重启行为符合预期。
8. Android 目标机型完成证书、CameraX、后台队列、断网续传与设备撤销测试。
9. 加密备份恢复到新目录成功，日志抽查不含秘密或不必要的对象内容。
10. 客户已书面确认数据授权、保留、销毁、备份、运维和事件响应责任人。
11. 真实科学仪器接入前，人员授权、设备联锁、校准和失败模式验收已完成。
12. 对外材料准确标记 `CODE_VERIFIED`、`HARDWARE_VERIFIED` 和 `DOMAIN_VALIDATED`，没有用软件测试替代硬件或领域结论。

通过以上检查后，才可以把部署状态从 `DEPLOYMENT_READY` 更新为 `HARDWARE_VERIFIED`；领域能力仍需单独的授权数据与专家验证。
